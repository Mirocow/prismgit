## [2.3.8] - 2026-09-29

### Добавлено — переключатель НИЖНЕЙ панели (журнал команд): третья кнопка из hero-ряда VS Code
- Пользователь попросил недостающую: «кнопку для нижнего сайдбар?» — референсный ряд VS Code это sidebar-left / **layout-panel** / sidebar-right, и средней кнопке в PrismGit не было соответствия: нижняя панель «Журнал команд» была достижима только через кнопку терминала / Ctrl+Shift+U / чип статус-бара — её видимость жила в App-уровневом `useState`, до которого тулбару не добраться
- Флаг переехал в `uiLayoutStore` (та же миграция, что v2.3.4 сделала для рейла сайдбара и панели деталей History) с сохранением в localStorage — открытое состояние панели теперь переживает рестарт; все старые точки входа (кнопка терминала, нативное меню Ctrl+Shift+U, чип статус-бара, ✕ панели, авто-открытие по ошибке с 30-секундной паузой) ведут к одному флагу стора
- Новая кнопка в углу хедера стоит МЕЖДУ двумя сайдбар-тогглами и рендерит точные оригинальные codicon'ы `layout-panel` (нижняя полоса залита — панель открыта) / `layout-panel-off` (полая, только разделитель — скрыта), 16×16 fill 16px, с локализованными подсказками на всех четырёх языках

## [2.3.7] - 2026-09-29

### Изменено — кнопки сворачивания сайдбаров теперь точно как в референсе VS Code
- Пользователь указал на hero-картинку из документации VS Code («вот посмотри как должны выглядеть кнопки сворачивания сайдбаров справа на картике»): её правый верхний ряд — это **layout-переключатели** титлбара — скруглённые коробки-иконки, у которых полоса панели **залита, пока панель открыта**, и полая (только разделитель) — пока свёрнута. Пиксельная экспертиза референса подтвердила точный набор иконок (`layout-sidebar-left`, `layout-panel`, `layout-sidebar-right-off`, `layout`)
- Кнопки в углу хедера PrismGit (левый сайдбар / правая панель деталей, справа от «Настроить панель инструментов») раньше использовали lucide-иконки панелей со стрелками — теперь это **точные path-данные оригинальных codicon'ов** (microsoft/vscode-codicons, 16×16, fill) в codicon-размере 16px, с той же семантикой состояния: открыто → залитая полоса, свёрнуто → полая. Внутрипанельные шевроны (рейл сайдбара, панель History) сохраняют свой вид

## [2.3.6] - 2026-09-29

### Исправлено — 3-way: полоса на средней панели при клике или фокусе
- Продолжение истории: «полоса появляется при клике на среднюю панель или при фокусе ее» — стоит кликнуть в панель «Результат» (или сфокусировать её), по краям панели вспыхивает яркая вертикальная полоса, а при потере фокуса исчезает. Первопричина (доказано живьём: computed-style + пиксельный диф): панель «Результат» — это **textarea размером во всю панель**, а глобальные правила фокуса рисовали вокруг неё акцентное кольцо 2px — Chromium матчит `:focus-visible` у текстовых полей **даже при клике мышью**, так что кольцо срабатывало на каждый клик
- Хуже того: то же глобальное правило ставило `position: relative`, перебивая `absolute` оверлея — textarea **схлопывалась до своей врождённой ширины `cols` (385→201px)**, и клик попадал кареткой не в тот символ
- Исправление: в кодовом редакторе **индикатор фокуса — каретка** (VS Code кольцо тоже не рисует) — кольцо/рамка/тень подавлены для merge-редактора отдельным классом `merge-editor-input`, плюс инлайновые `outline: none` / `position: absolute`, которые не сможет перебить никакое будущее глобальное правило. Колечки фокуса для клавиатуры везде остальном (кнопки, поля, диалоги) не тронуты

## [2.3.5] - 2026-09-29

### Исправлено — 3-way: «полосой в центральной панели» оказались маркеры конфликта
- Строки-маркеры `<<<<<<<` / `=======` / `>>>>>>>` в панели «Результат» несли красную заливку на 35% во всю ширину — при конфликте в середине файла это выглядело ровно как «полоса по центру центральной панели» (а красный читается как ошибка). Маркеры — структурный шум, а не контент: теперь у них нейтральный фон и приглушённый текст, а контентные строки ours/theirs сохраняют зелёный/синий сигнал — смягчённый до 20%, чтобы блок читался как одна спокойная подсвеченная область, а не агрессивные полосы

### Изменено — Назад/Вперёд действует в рамках проекта, глубина настраивается
- Переключение открытого репозитория теперь СБРАСЫВАЕТ стек навигации («кнопки вперед назад должны работать только в рамках проекта»)
- В истории **10 шагов по умолчанию** (было неограниченное 60), количество настраивается в Настройки → «Сайдбар и навигация» → «Шагов в истории Назад/Вперёд» (5–100); старые записи вытесняются при превышении лимита

### Исправлено — History: фильтры автора/дат теперь работают НА СТОРОНЕ git
- Отчёт пользователя: вводишь автора, жмёшь рефреш — ничего не меняется; коммиты появлялись только после прокрутки всей истории. Причина: фильтры автора/дат применялись КЛИЕНТСКИ по первой загруженной сотне коммитов — коммиты автора дальше первой страницы фильтр не видел. Теперь сам рефреш запускает `git log --author=<шаблон> --since/--until` (без учёта регистра, по «Имя <email>»), пейджинг сохраняет фильтры, а фильтр применяется автоматически через 300мс после ввода (с дебаунсом — один проход, а не по одному на букву)
- Заодно исправлен латентный баг порядка аргументов: `--grep`/`--author`/`--since`/`--until` теперь всегда идут ДО разделителя путей `-- <файл>` (опции после `--` git считает путями — комбинации автор+файл и grep+файл молча возвращали пусто)

## [2.3.4] - 2026-09-29

### Исправлено — баг интервалов: три раунда «увеличить отступы» были не видны
- **Корень (каскадный баг): собственный сброс приложения `* { margin: 0; padding: 0 }` компилировался в `@layer utilities` ПОСЛЕ правил `space-y-*` Tailwind** — v4 отдаёт space-утилиты через `:where()` (специфичность 0), поэтому сброс молча перебивал ВСЕ `space-y-*`/`space-x-*` утилиты во всём приложении: отступы между элементами вообще не отрисовывались. Именно поэтому интервалы в Settings и диалогах не менялись визуально в v2.3.1–v2.3.3, как бы классы ни увеличивали. Избыточный сброс удалён (preflight Tailwind уже обнуляет маржины в `@layer base`) — теперь каждый `space-*` класс работает как задумано, во всех инструментах и диалогах
- Поверх фикса интервалы в Settings увеличены: главные панели `space-y-8` (32px), вторичные 6/5, списки сортировки 2.5

### Исправлено — «!»-подсказки не показывали контент
- Тултип InfoHint не отображался никогда: стек-вариант `group-hover:group-focus:block` требует наведения И фокуса одновременно (а кнопка глотает mousedown, и фокус не приходит) — заменено на `group-hover:block group-focus-within:block`. Маркеры «!» теперь показывают текст подсказки при наведении и с клавиатуры

### Добавлено — кнопки сворачивания в углу тулбара (как в VS Code)
- Два переключателя СПРАВА от кнопки «Настроить панель инструментов»: сворачивание/разворачивание левого сайдбара (рельс 48px) и правой панели деталей коммита. Флаги переехали в общий `uiLayoutStore` (те же ключи localStorage — сохранённое состояние не теряется); тулбар, рельс сайдбара и панель History синхронны

### Исправлено — кнопки инструмента LFS видны только при наведении
- «История файла» и кнопка блокировки в строках файлов теперь всегда видимы (60% в покое), как и в Поиске из v2.3.3

### Добавлено — AI-ассистент умеет пользоваться ВСЕМИ инструментами (18/18)
- 10 новых движков (всего 41): `get_reflog` (Reflog), `list_submodules` + `submodule_update` (Submodules), `lfs_overview` + `lfs_sync` (LFS), `bisect` (вся машина состояний: status/start/good/bad/skip/reset/log), `gitflow_overview` (конфигурация flow + ветки по типам + роль текущей ветки), `recyclable_commits` (потерянные коммиты), `list_reviews` (распределённые ревью из git notes), `list_pull_requests` (PR GitHub / MR GitLab с детектом провайдера и подсказкой про токен)
- Системный промпт учит модель, когда брать каждый движок (правила 24–27), включая цикл bisect («протестируй кандидата и ответь good/bad»)

## [2.3.1] - 2026-09-29

### Исправлено — «приложение тупит на всех инструментах» (замерено, затем исправлено)
- **Все читающие git-команды выполняются в выделенном git-воркере** вместо главного процесса Electron. Главный процесс — брокер всего IPC рендерера: пока он качал вывод git, клики и обновления всех инструментов стояли в очереди. Замер на репозитории 20k коммитов / 31 ветка: открытие History блокировало main-loop на 119ms (на macOS спавны в 3-5 раз дороже); после роутера ни один инструмент не блокирует дольше 2.4ms. Коалесцирование in-flight и meta-TTL 1s не изменились; в vitest команды идут in-process — все 2017 тестов видят прежнее поведение
- **Спавны воркера репортятся в Консоль операций** — журнал команд показывает ВСЮ git-активность с длительностями независимо от процесса (39 из 47 команд на фикуре выполнились в воркере)
- `git remote -v` (самая медленная команда в burst открытия History, 384ms) теперь кешируется 60с — набор ремоутов меняется только через наблюдаемые записи git
- **GitLab projectId heal watchdog в PR/Ревью** получил бэкофф: отвергнутый токен или недоступный GitLab раньше дёргали сеть каждые 1.5с, пока открыта страница (~40 запросов/мин); теперь задержка удваивается до 30с, успех сбрасывает
- **3-секундный полл Bisect** работает только при активном bisect (раньше — каждые 3с, пока открыт инструмент)

### Добавлено — из Search к коммиту, внёсшему изменение
- Каждая строка находки (git grep) получила действия: **Blame на этой строке** (скролл + подсветка найденной строки, видно кто внёс), **История файла** (сразу отфильтрованная по нему — «фильтровать сразу по файлу»), **Diff**; заголовок группы файла — полный набор Changes/Diff/Blame/History
- Переход History-из-Search фильтрует граф по файлу (чип path-filter) и может сразу выбрать коммит
- Одноразовый `blameFocusLine` в selection store питает фокусированный переход (потребляется один раз, чистится при смене репозитория)

### Добавлено — ИИ-ассистент освоил инструменты Search и Blame
- Новые инструменты `search_code` (git grep — движок вкладки «Содержимое» Поиска) и `blame_file` (построчный blame, сгруппированный в блоки коммитов) — зарегистрированы в чате с подсказками выбора («кто внёс эту строку?» → blame_file; «где используется X?» → search_code → read_file)

### Исправлено — взаимодействие фильтров и поиска в History
- Активация чипа/автора/даты при активном текстовом поиске теперь **сбрасывает поиск** — фильтр работает по ВСЕМ коммитам, а не по пересечению с найденным
- У каждого фильтра (History, Branches, Changes) появился **✕ — сброс** + Esc — поиск больше не «застревает»

### Изменено — воздух в диалогах и настройках
- Группы полей диалогов и строки настроек/списков разнесены шире (space-y-4, выше строки списков)

## [2.2.0] - 2026-09-28

### Добавлено — каждая конфликтная операция теперь РЕАГИРУЕТ
- **Единая матрица реакций на конфликты** — pull (стратегии merge/rebase/ff-only), merge, rebase, cherry-pick, revert, stash pop/apply, завершение git-flow (×4 сценария), squash-to-branch, 3-way патч и авто-stash AI — ВСЕ переходят к решателю конфликтов страницы «Изменения» с баннером выполняемой операции («Слияние/Rebase/Применяется» + Продолжить / Пропустить / Прервать), секцией «Конфликты» и операционным предупреждением
- **Git-Flow никогда не продолжает работу после конфликта** — сценарии завершения останавливаются на конфликтном слиянии: ни тега, ни удаления ветви, ни push в конфликтном состоянии
- **Честный stash pop/apply** — simple-git считает конфликтный `git stash pop|apply` успехом; пост-проверка статуса теперь распознаёт конфликтное состояние, выбрасывает типизированную ошибку с `.conflicts`, сохраняет запись stash и открывает решатель (раньше: тост об успехе + сброс выбора, а дерево наполнялось маркерами конфликтов)
- Проверено на живом приложении: `scripts/verify-conflict-reactions.mjs` — 17/17 (RU)

Подключён во все точки обработки ошибок push (тулбар push/sync/Push-To, «Коммит и Push», завершение git-flow)
- **Исправлен IPC-фильтр ошибок** — wrap() в `electron/ipc/git.ts` оставлял только строки `error:/fatal:`: строки `! [rejected]` и `remote: GitLab:` ВЫРЕЗАЛИСЬ до рендера, поэтому диалог в принципе не мог открыться. Теперь строки rejected]/remote:/hint: проходят
- **Значки конфликтов PR/MR** — GitLab `merge_status` / GitHub `mergeable` в строках списков и заголовке ревью; кнопка Merge заблокирована с подсказкой, когда слияние невозможно
