# Журнал изменений

Все заметные изменения PrismGit документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект следует [Семантическому версионированию](https://semver.org/lang/ru/).

**Другие языки:** [English](CHANGELOG.md) · [中文](CHANGELOG.zh.md) · [Deutsch](CHANGELOG.de.md)

## [2.3.0] - 2026-09-29

### Добавлено — Навигация Назад/Вперёд как в браузере
- **Кнопки Назад/Вперёд в тулбаре** + Alt+← / Alt+→. Отдельный стек истории ведёт только след пользователя; срез «хвоста вперёд» при новом переходе — как в браузере
- Комбинации внесены в шпаргалку горячих клавиш (группа «Навигация»)

### Добавлено — Сворачивание панелей в стиле VS Code
- **Левый сайдбар** сворачивается в панель значков 48px (иконки инструментов + живой счётчик изменений + тема/настройки внизу); клик по стрелке возвращает прежнюю ширину. Состояние сохраняется
- **Панель коммита в History** (правый сайдбар) сворачивается в полоску 24px — граф занимает всю ширину

### Добавлено — Пользовательские темы + отбор тем
- **В выборе тем осталось 6** (Ayu Light, One Dark, Simple, Material, Discord, Светлое окно + тёмный сайдбар); сохранённый выбор со старой темой автоматически переезжает на ближайшую из отобранных
- **Визуальный редактор темы** («Создать тему…»): 15 цветов (поверхности, ЦВЕТА ТЕКСТА, акцент, границы, статусы, фон сайдбара) + флажок тёмной + живой предпросмотр. Тема применяется через собственный селектор `data-theme="custom-*"` с производными оттенками — цвет текста меняется во всех инструментах
- Поле «Сайдбар» — способ собрать «тёмный сайдбар + светлое окно» (как в VS Code); читаемость текста сайдбара считается автоматически
- Заменяет JSON-поле «Переопределения темы» (только для опытных)

### Добавлено — Горячие клавиши на все инструменты + настраиваемый порядок
- У каждого инструмента ровно одна клавиша: Ctrl+1..9 (основные) + Alt+1..9 (остальные — раньше Alt+1..6 дублировали Ctrl+1..6)
- **Настройки → Интерфейс → «Сайдбар и навигация»**: порядок инструментов (↑/↓, сохраняется), переназначение любой клавиши из свободных слотов («—» снять; занятая комбинация освобождается у прошлого владельца), сброс
- Горячие клавиши инструментов работают и из полей ввода (как в браузере)

### Добавлено — Контекст коммита в History
- **«Ветки, содержащие коммит»** — бейджи веток в карточке коммита (`git branch --contains` + `-r`, кэш по SHA); клик по локальной ветке переключает граф на неё
- **Фильтр по автору в один клик** — клик по имени автора в карточке задаёт фильтр; кнопка копирования даёт «Имя <email>»

### Исправлено — Счётчики, второй заход
- **Сводка в Ветках** показывает общие числа по репозиторию (при активном поиске числа «сжимались» и расходились с инструментами Теги/Stashes)
- **Чип «С тегами (N)»** считается по отфильтрованному набору — при активном текстовом/авторском/датском фильтре число совпадает с тем, что покажет сам фильтр
- **Диалог информации о репозитории** показывает локальные И удалённые ветки раздельно; статистика дополнилась подсчётом `git branch -r`
- Из History убраны мёртвые загрузчики (stash/reflog грузились при каждом обновлении для секций, которых больше нет)

### Исправлено — Шквал 401-тостов от «мертвых» интеграций
- Отклонённый токен GitHub (401 Bad credentials) на странице Pull Requests — теперь проблема АВТОРИЗАЦИИ, а не загрузки: ни одного тоста об ошибке, вместо него внутристраничная форма входа, повторные заходы не шлют запросов (один запрос вместо 3+)
- loadPRs защищён от повторов (in-flight/last-key): смена `loading` при детекте провайдера больше не вызывает повторную загрузку; кнопка «Обновить» — явный путь повтора

### Изменено — Настройки без дубликатов и с пояснениями
- **Две панели «Внешние инструменты» объединены** (поля имён diff.tool/merge.tool переехали к командам, которые настраивают)
- **Направляющие строк коммита**: мёртвые числовые поля удалены — селектор в «Командах» единственный владелец
- **«!»-хитбоксы** (всплывающие пояснения) у настроек, вызывающих вопросы: интервал и область фоновой проверки, лимит reflog, контраст, сайдбар и навигация
- Захардкоженные английские подзаголовки AI-панели локализованы

## [2.2.0] - 2026-09-28

### Добавлено — каждая конфликтная операция теперь РЕАГИРУЕТ
- **Единая матрица реакций на конфликты** — pull (стратегии merge/rebase/ff-only), merge, rebase, cherry-pick, revert, stash pop/apply, завершение git-flow (×4 сценария), squash-to-branch, 3-way патч и авто-stash AI — ВСЕ переходят к решателю конфликтов страницы «Изменения» с баннером выполняемой операции («Слияние/Rebase/Применяется» + Продолжить / Пропустить / Прервать), секцией «Конфликты» и операционным предупреждением
- **Git-Flow никогда не продолжает работу после конфликта** — сценарии завершения останавливаются на конфликтном слиянии: ни тега, ни удаления ветви, ни push в конфликтном состоянии
- **Честный stash pop/apply** — simple-git считает конфликтный `git stash pop|apply` успехом; пост-проверка статуса теперь распознаёт конфликтное состояние, выбрасывает типизированную ошибку с `.conflicts`, сохраняет запись stash и открывает решатель (раньше: тост об успехе + сброс выбора, а дерево наполнялось маркерами конфликтов)
- Проверено на живом приложении: `scripts/verify-conflict-reactions.mjs` — 17/17 (RU)

### Добавлено — восстановление после отклонения push (удалённые конфликты)
- **PushRejectionDialog** — отклонённые git-ом push открывают диалог с классификацией по причине и восстановлением для каждой: non-fast-forward → «Стянуть и слить» + автоматический повтор push; устаревший force-with-lease → fetch + повтор с новым lease; защищённая ветка → создать MR/PR; блокировки политикой с объяснением. Подключён во все точки обработки ошибок push (тулбар push/sync/Push-To, «Коммит и Push», завершение git-flow)
- **Исправлен IPC-фильтр ошибок** — wrap() в `electron/ipc/git.ts` оставлял только строки `error:/fatal:`: строки `! [rejected]` и `remote: GitLab:` ВЫРЕЗАЛИСЬ до рендера, поэтому диалог в принципе не мог открыться. Теперь строки rejected]/remote:/hint: проходят
- **Значки конфликтов PR/MR** — GitLab `merge_status` / GitHub `mergeable` в строках списков и заголовке ревью; кнопка Merge заблокирована с подсказкой, когда слияние невозможно
- Проверено на живом приложении: `scripts/verify-push-rejections.mjs` — 16/16 (диалог non-FF + авто-повтор pull-merge, force-with-lease, fetch-retry при устаревшем lease)

### Добавлено — сквош группы коммитов в другую ветку
- Выберите диапазон коммитов в Истории (или группу PR/MR из Pull Requests/Ревью) и приземлите его в другую ветвь ОДНИМ коммитом — существующую или НОВУЮ, с полной обработкой конфликтов в диалоге
- Старый API-набор сквоша заменён на конфликтно-осознанный; E2E сквоша всего PR сохранён совместимым

### Добавлено — менеджер секретов (Настройки → Безопасность)
- **Секция сохранённых секретов** — каждая запись зашифрованного хранилища выводится списком (только метаданные: namespace, имя, признак шифрования) с группировкой по категориям: токены доступа, пароли репозиториев/remotes, ключи AI-провайдеров, GitHub, SSH-парольные фразы
- **Копировать / Заменить / Удалить для каждой записи** — значения никогда не отображаются; «копировать» раскрывает одно значение сразу в буфер, «заменить» сохраняет новое, «удалить» убирает запись (с подтверждением)
- **Добавить секрет** — вручную зарегистрировать секрет (токен, пароль remote для пути репозитория + имени remote и т.д.), шифруемый с первого байта
- Новые IPC: `credentials:list` / `credentials:set` / `credentials:delete` / `credentials:reveal`

### Добавлено — автор коммита по умолчанию (Настройки → Git)
- **«Автор коммита по умолчанию»** (gitUserName / gitUserEmail) в Настройках → Проект → Git с кнопкой «Применить к текущему репозиторию»
- Новые репозитории, созданные или клонированные в PrismGit, автоматически получают идентичность в локальных `user.name` / `user.email` — больше нет «Please tell me who you are» при первом коммите
- `commit()` повторяется один раз с идентичностью по умолчанию как `-c`-оверрайдами, когда git отказывает из-за отсутствия настроенной идентичности; иначе ошибка объясняет, где её задать

### Исправлено — счётчики (аудит видимых пользователю чисел)
- **Чип «С тегами (N)» в Истории** — N теперь число ПОМЕЧЕННЫХ КОММИТОВ В ПРЕДСТАВЛЕНИИ (ровно столько, сколько фильтр покажет для текущего выбора ветвей); тултип несёт оба числа (в представлении + по всему репозиторию). Было: allTags.length — тег на ветви вне представления расходил чип со строками
- **«Теги на этом коммите (N)»** — считаются только теги, указывающие на коммит (два тега на одном коммите → (2), имена перечислены)
- **Русская грамматика сводки Веток** — новый опциональный синтаксис множественного числа в t(): `{name|one|few|many}` выбирает форму CLDR («1 локальная · 2 локальные · 5 локальных · 6 тегов»); en/zh/de сохраняют простые плейсхолдеры и рендерятся байт-в-байт
- **Сайдбар следует языку при запуске** — подписи навигации замораживались при загрузке модуля, поэтому первый запуск RU-профиля показывал английский сайдбар до ручного обновления; NAV_ITEMS теперь вычисляется при каждом рендере (сайдбар, палитра команд, баннеры подсказок)
- Синхронизация счётчиков между инструментами: удаление тега в «Тегах» немедленно обновляет чип Истории
- Проверено на живом приложении: `scripts/verify-counters.mjs` — 17/17 против эталона git CLI

### Исправлено — «Не удалось сохранить настройки» (gpg.program)
- Настройки репозитория → Подпись не сохранялись: simple-git блокирует `git config gpg.program` (и другие «небезопасные» ключи) без `allowUnsafeGpgProgram`. `configSet` / `configUnset` теперь распознают отказ плагина и повторяют запись на экземпляре с разрешённой записью конфига — явные правки пользователя в GUI-клиенте и есть намерение
- Вкладка «Подпись» больше не пишет `gpg.program` безусловно: пустые поля УДАЛЯЮТСЯ из `.git/config` вместо записи (также исправлены нестираемый user.signingkey и опасная запись `user.name=""`, ломавшая каждый коммит ошибкой «empty ident name not allowed»)

### Исправлено — GitLab / поверхности PR
- **Создание MR для репозитория GitLab теперь работает** — диалог создания в Pull Requests вызывал GitHub API даже для GitLab-репозиториев (гарантированный провал при обещанном «создании» для обоих провайдеров); теперь подключён давно существующий IPC `gitlab:createMergeRequest` — проверено на живом приложении созданием релизного MR v2.2.0
- **GitLab apiJson следит за 3xx-редиректами** — переименованные/перенесённые проекты (gitclient → prismgit) ломали список MR тихими 404
- **Действия в строках Pull Requests видимы и понятны** — криптоиконки при наведении → постоянные подписанные кнопки + контекстное меню (Открыть в Ревью / браузер / Сквош / Копировать группу)

### Исправлено — установка / упаковка
- **`make install` переживает 404 локального npm-зеркала** — `scripts/npm-install-with-retry.sh` оборачивает npm install/ci, читает результат из собственного вывода npm (tee съедает коды выхода), при E404 автоматически повторяет один раз с `--registry=https://registry.npmjs.org`; EBADENGINE получает дружелюбную подсказку обновить Node; убитый запуск не может подделать успех
- Метаданные deb-упаковки + производственный smoke E2E — упаковка, выживающая на реальных машинах

### Исправлено — стабильность
- **Watchdog завершения** — закрытие больше не зависает: жёсткий watchdog 3 с, дочерние процессы воркера не остаются сиротами
- **Устранено зависание при переключении репозитория** — статус, слежение за рабочей директорией и чтения выполняются в git-воркере; исправление плотности (v3.6)
- **Буря fetch фонового remote-статуса** — разорван буст-цикл, зависшие fetch убиваются, опрос отвязан от очереди переднего плана; fetch статуса remote перенесён в выделенный utilityProcess
- **Изоляция перерисовок** — перерисовки на уровень нажатия клавиши/токена/кадра изолированы; убран шторм 5-секундной полной перерисовки дерева от обновлений статуса
- **i18n-вёрстка** — интерфейс больше не ломается от длины строк RU/DE

### Изменено — производительность: медленные git-операции после проблем LFS
- Сетевые команды (fetch / pull / push / ls-remote) больше не выполняются на общем per-repo экземпляре simple-git (`maxConcurrentProcesses: 2`), который используют все локальные операции — медленная или зависшая сетевая команда (недоступный LFS-сервер, ждущий ввода диалог учётных данных, огромный fetch) занимала 2 слота очереди и блокировала ВСЕ git-операции репозитория
- Все сетевые команды выполняются с `GIT_TERMINAL_PROMPT=0` — неотвеченный запрос учётных данных быстро падает с понятной ошибкой вместо невидимого зависания (как в push)

### Изменено — зависимости (все актуальны)
- **simple-git 3 → 4** — миграция на именованные импорты; новый страж окружения укрощён (контракт `allowEnvironment` для GIT_*-ключей, закреплён пробой)
- vite 8.3, vitest 5, @types/node 26, @tauri-apps/* 2.12 (React 19 / Electron 44 / TypeScript 7 / Tailwind 4 были актуальны)

### Тесты
- **1963 проходят** (было 1009 в 2.1.0) / 0 упавших / 34 пропусков, зависящих от окружения; tsc без ошибок
- Новые слои: интеграционный набор реакций на конфликты (реальный bare remote, настоящее расхождение), сценарии отклонения push (non-FF, устаревший lease, эмуляция защищённого pre-receive), E2E счётчиков, движок множественного числа i18n, конфликтно-осознанный API сквоша, корпоративный QA-набор производительности (генератор monster-репо, CDP память/DOM/FPS + аудит зомби)
- `tests/integration/gitService.identityConfig.test.ts` — set/unset gpg.program, идентичность при init, fallback коммита, сообщение об ошибке без идентичности
- `scripts/secrets-smoke.cjs` расширен проверками менеджера секретов (список только метаданных, set+reveal, delete)
